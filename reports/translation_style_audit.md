## 一、摘要

本轮审计以 `DIRECTOR_REVIEW_ROUND4.md` 的 LLC 术语基准为主控标准。抽查结果显示，稿件中最集中的术语问题有三类：

1. **核心专名仍沿用旧译**：`城市`、`异常体`、`卡隆`、`维吉利乌斯`、`旅秀`、`莫尔索`、`身份系统`、`管理者（边狱）` 等多处与 LLC 基准不一致。
2. **不同语境未区分**：`管理者` 在脑叶公司语境可保留，但在 Limbus Company / Dante 语境应改为 `执行经理`；`身份` 泛指身份时可保留，但系统术语应改为 `人格`。
3. **历史类读品文风有局部偏百科化和推断过实问题**：尤其是异常体机制、光之种计划、罪人文学原型、Limbus 运营章节中，部分段落从“事件记录”滑向“机制讲解/主题论文/社区推断定论”。

主控整合时建议优先处理术语表与索引类文件，再处理正文叙述。术语表是全书自动整合和后续校验的源头，如果不先统一，`BOOK.md` 重新生成后仍会携带旧译。

## 四、文风问题

### 1. 过度设定讲解：`manuscript/ch_05_abnormality_history.md`

- 第 28-62 行连续解释异想体类型、工作系统、风险等级、Qliphoth 计数器，信息密度接近游戏机制百科。建议保留与历史事件相关的最低解释，把分类、工作类型和风险等级压缩成一段，并把重点转回“这些制度如何塑造脑叶公司的运行和事故”。
- 第 80-100 行对连锁崩溃、心理镜像、日常张力的分析较长，适合作为主题评论，但作为历史类读品可删减三分之一，减少“每一个计数器的小幅变化”这类体验化描写。

### 2. 推断过实：`manuscript/ch_06_seed_of_light.md`

- 第 16 行：“他的全部行动都散发着一种接近于赎罪或纪念的驱动力”属于人物心理判断，建议改为“可被理解为带有赎罪或纪念意味”。
- 第 34-36 行：“光之种计划需要收集巨量的光”“还需要质的匹配”表述像明确技术设定。建议加“从游戏流程和叙事结构看”，避免把机制解释写成官方工程说明。
- 第 52-56 行：“每一原质的心结被解开……必要条件”“作为实验对象接受治疗方案”偏论文式阐释。建议改为“叙事上呈现为管理者必须逐步面对各 Sephirah 的创伤”。

### 3. 百科感过强：`manuscript/ch_13_sinner_biographies.md`

- 第 22-120 行每位罪人均按“文学原型—人格特征—篇章功能”模板展开，结构清楚但像角色百科。建议主控整合时挑选与事件链直接相关的内容，弱化文学原典梗概。
- 第 48-62 行良秀、默尔索两节尤其偏角色说明，缺少“他们在金枝旅程中造成了什么历史性后果”。建议缩短为人物索引式段落，等待其个人篇章展开后再扩写。
- 第 134 行把异想体/扭曲体与罪人创伤的映射写成固定规则，建议降格为“常见叙事安排”。

### 4. 设定解释压过事件记录：`manuscript/ch_12_limbus_system.md`

- 第 52-56 行从人格系统、E.G.O. 装备讲到平行维度和抽卡运营，容易从历史叙述转成游戏系统说明。建议拆分：历史正文只写“边狱公司使用人格与 E.G.O. 作为作战资源”；机制和商业模式放入附录或持续运营章。
- 第 28-32 行对《Leviathan》如何解释维吉里乌斯动机写得较满，尤其“从根本上改变了自身对力量、责任和人际关系的理解”“不干涉并非冷漠”等为强解释。建议改为“可为其后续态度提供背景”。

### 5. 现实运营分析过多：`manuscript/ch_15_unfolding_history.md`

- 第 14-16、28-30 行对免费游玩、抽卡克制、通行证友好度作较多评价，像游戏商业模式评论。建议保留“持续运营会影响记录时效性”这一历史写作问题，删减价值判断。
- 第 48-50 行把 Project Moon 官方渠道和实时版本信息写进“关键人物”，分类不自然。建议移至“资料更新说明”或附录维护流程。
- 第 89 行具体移动 GPU 兼容性风险属于技术公告细节，对历史类读品价值有限。建议放入维护日志，不放正文。

### 6. 主题判断过密：`manuscript/ch_01_city_order.md`

- 第 30、36、58-62 行大量使用“本质上”“最核心”“不存在真正的无辜者”等强判断，文气有力但容易压过事实记录。建议保留一两处作为章节收束，其余改为事件化描述。
- 第 40-44 行以罗兰、安吉拉、Gebura 作为都市秩序例证时，若缺少具体事件来源，容易像主题论文。建议用已登记事件 ID 串联，减少抽象结论。

## 五、主控整合建议

1. **先统一术语源头**：优先修 `notes/terminology.md` 与 `manuscript/appendix_f_terminology.md`，再批量处理正文和索引，最后重新生成 `manuscript/BOOK.md`。
2. **建立语境规则**：`管理者` 仅保留给脑叶公司设施 Manager / X；Dante 一律 `执行经理`。`身份` 仅保留普通语义；Limbus 系统术语一律 `人格`。
3. **专名替换不要机械全局替换**：`城市` 需要人工判定，The City 专名改为 `都市`，普通语义如“现实世界城市”“城市级事件”可视语境保留或改写。
4. **卡戎、维吉里乌斯、良秀、默尔索可安全批量替换**：这些在抽查范围内基本均为专名旧译，建议主控统一替换后抽样复核。
5. **文风修订原则**：删减机制清单、减少“本质上/必然/唯一/直接证明”等定论词，把社区推断改为“可能、可理解为、叙事上呈现为”。

7. **新增校验词表**：建议 Agent C 或主控脚本加入旧译检测：`异常体|卡隆|维吉利乌斯|旅秀|莫尔索|身份系统|边狱巴士|巴士部|执行管理者|经理人`。其中 `城市`、`身份`、`管理者` 需人工复核，不宜自动报错为必改。
